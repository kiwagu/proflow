# Local nginx edge

- Serves `proflow.local` (gateway UI) and `api.proflow.local` (Supabase API) on HTTPS.
- Routes app traffic to local `apps/web` dev server via `PROFLOW_DEV_APP_PORT` (default `3000`).
- Routes API traffic to Kong via `PROFLOW_SUPABASE_UPSTREAM_HOST` / `PROFLOW_SUPABASE_UPSTREAM_PORT` (defaults `host.docker.internal:8000`).
- TLS certs are loaded from `infra/dev/nginx/ssl/proflow.local.crt` and `proflow.local.key`.

## Quick start

1. Add hosts:
   - `127.0.0.1 proflow.local api.proflow.local`
2. Start local infra:
   - `make stack-up` (or `./infra/dev/stack-up.sh`)
3. Start app dev servers from repo root:
   - `bun run dev`
4. Open:
   - `https://proflow.local`
   - `https://proflow.local/platform`
   - `https://proflow.local/author`

## Configuration

Set overrides in `infra/dev/.env` (examples in `.env.example`):

- `PROFLOW_DEV_APP_PORT` — upstream for UI gateway (`apps/web`)
- `PROFLOW_SUPABASE_UPSTREAM_HOST` — Kong upstream host for `api.proflow.local`
- `PROFLOW_SUPABASE_UPSTREAM_PORT` — Kong upstream port

In apps:

- `apps/platform/.env` and `apps/author/.env` should use:
  - `NEXT_PUBLIC_SUPABASE_URL=https://api.proflow.local`

## TLS setup

- Self-signed (default): generated by `./infra/dev/nginx/generate-ssl.sh`
- mkcert (recommended):
  ```bash
  mkcert -install
  mkcert proflow.local api.proflow.local
  ```
  Then copy generated files to:
  - `infra/dev/nginx/ssl/proflow.local.crt`
  - `infra/dev/nginx/ssl/proflow.local.key`

  > Running mkcert from a snap-confined shell (e.g. VS Code's integrated
  > terminal) can put `CAROOT` under `~/snap/.../mkcert` instead of
  > `~/.local/share/mkcert`, so `mkcert -install` trusts a different CA than the
  > one that signed the cert. Pin `CAROOT=~/.local/share/mkcert` for both
  > `mkcert <domains>` and `mkcert -install` so they match. Symptom of a
  > mismatch: a silent redirect loop back to the platform login page (the
  > browser sign-in returns 200, but server-side `getUser()` fails TLS).

## Troubleshooting

- `CORS failed` with duplicate `Access-Control-Allow-Origin`
  - Ensure nginx is running latest template and CORS is normalized at edge.
  - Recreate nginx container: `docker compose up -d --force-recreate nginx` in `infra/dev`.

- `UNABLE_TO_VERIFY_LEAF_SIGNATURE` in Next server logs
  - Ensure Node uses system CAs (`--use-system-ca` in app scripts).
  - Ensure cert SAN includes both `proflow.local` and `api.proflow.local`.

- Login redirect loop: sign-in returns 200 but the app bounces back to the platform login page
  - The local CA is not trusted by Node, so server-side `getUser()` fails TLS. Run `mkcert -install` (see TLS setup) and confirm `--use-system-ca` is set in the app dev scripts.
  - If you already ran `mkcert -install`, check for the CAROOT/snap mismatch noted in TLS setup.

- `Blocked cross-origin request to .../_next/webpack-hmr`
  - Add `proflow.local`/`https://proflow.local` to `allowedDevOrigins` in each Next app and restart dev servers.

- `api.proflow.local` returns `502`
  - Verify Kong is reachable at configured upstream host/port.
  - Verify nginx container has refreshed env values (recreate, not just restart).

## Notes for production

- Use dedicated API host (e.g. `api.example.com`) behind TLS.
- Keep UI/API origins explicit and configure CORS once at edge.
- Align Supabase `API_EXTERNAL_URL` and public URLs with the real API origin.
